LLMs yearn for the mines

how one gradient update lobotomized my RuneScape bot

training
failure
grpo
Published

June 1, 2026

tl;dr

Step 0: the model earns 956 XP chopping trees and fighting giant rats on a live RuneScape server. Step 1: it repeats "Let me mine the rock.\n</think>\n" 150 times until it hits the 2048 token limit. Qwen started yearning for the mines, and then the mines were its undoing.

the setup

Qwen3.5-0.8B with zero post-training was already surprisingly good at playing RuneScape via tool calls — good enough that I got impatient and kicked off a live GRPO training run before thinking too hard about hyperparameters. The model could analyze game state, count inventory slots, and pick reasonable actions out of the box. I wanted to see what happened when I reinforced that with real XP rewards on the LostCity server.

The rs-sdk runs multiplied XP rates to speed up training, so the model levels fast even in short rollouts.

The config:

model:
  model_name_or_path: Qwen/Qwen3.5-0.8B
  quantize_int4: false
  max_new_tokens: 2048
grpo:
1  group_size: 2
2  kl_coeff: 0.0
3  learning_rate: 3e-5
env:
  max_actions: 5
  use_heuristic_reward: false
1
Overrode from 4 to 2 on the command line — each rollout takes ~100s on the live server
2
Skipped loading the reference model to save VRAM on the 4090
3
3x the base config’s LR. No warmup, no decay.

the fall

That’s not a gradual decline. That’s a phase transition. One gradient update — computed from 2 rollouts with 2 update epochs — and the model forgot how to form sentences.

Loss and KL both flatline at zero from step 2 onward — every rollout scores the same -1.0, advantages are all zero, gradients are zero. The model is frozen in its collapsed state with no learning signal to escape.

Cancelled after step 7. 22 minutes of GPU time. The model spent 18 of those generating variations of “Let me do that.”

The raw generation logs are the real story here. This is a 0.8B model going from competent agentic reasoning to broken record in a single gradient step.

Then the gradient update happens.

steps 3–7 — continued decay

It only gets worse. The repetition unit gets shorter each step as the model’s vocabulary collapses:

Step Output
3 Let meThis game state state. Word boundaries dissolving
5 Let mehelp memine the rock. "memine" — four fragments fused into one
6 Let me\n</think>\n ×200 All semantic content gone
7 HP statestatestatestatestate It remembers game states have HP. That’s all it remembers.

I pulled the plug after step 7.

After the first gradient step, every generated token is wasted.

what went wrong

The unquantized 0.8B model + 2048-token sequences + optimizer states put me near 24GB on the 4090. The reference model for KL adds ~1.6GB. I cut corners to avoid OOMs — corners that removed every guardrail against mode collapse.

Three contributing factors:

Factor Setting Effect
No KL penalty kl_coeff=0.0 No anchor to pretrained distribution. The clipped surrogate alone cannot prevent arbitrarily large policy drift in a single update.
No LR schedule lr=3e-5, flat 3× the base config (1e-5). No warmup attenuates the first gradient; no decay reduces later ones.
group_size=2 Overridden from 4 Advantage estimate is binary: one rollout gets +1, the other -1. No signal about magnitude.
